DeltCRM Payroll Module
All Phases and Optimized Codex Prompts
Implementation handbook for Phases 1-5
Prepared for the DeltCRM multi-tenant HRMS platform
Source roadmap: DeltCRM Payroll Module KT and Implementation Brief, 26 July 2026
How to use this handbook
Run prompts strictly in sequence. Do not start the next prompt until the current prompt reports readiness.
Paste one prompt into Codex per execution. Large phases are split into focused implementation prompts.
Keep implementation checks focused during development. Use the final hardening phase for exhaustive release verification.
Do not allow Codex to introduce future-phase functionality early. Each prompt contains explicit exclusions.
After every prompt, review the changed files, test results, remaining blockers and scope confirmation.
Five-phase delivery roadmap
Global rules for every prompt
Inspect and reuse existing DeltCRM patterns before creating new infrastructure.
Keep Payroll as a tenant-scoped top-level product boundary using CQRS, focused ports and transactions.
Use integer minor units with ISO currency; support both two-decimal and three-decimal currencies.
Never depend on live mutable attendance for approved or finalized payroll.
Do not log protected payroll, bank, tax, payslip or formula-input data.
Regenerate OpenAPI and committed TypeScript/Flutter contracts when APIs change.
Document pre-existing non-Payroll failures separately instead of hiding them.
Do not weaken tests, disable checks or introduce broad unrelated refactors.
